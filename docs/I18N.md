# Internationalization

## Policy

- **English is the source language and the default.** New code, comments, docstrings, tests, API errors, logs, commit messages, and configuration keys are written in English.
- **Spanish is a full UI translation.** User-facing UI text lives in `site/i18n/es.json`.
- **Do not translate protocol terms** such as `hub`, `tailnet`, `mesh`, `release`, `canary`, `rollback`, `quorum`, `Funnel`, `Serve`, or `Taildrop` when they refer to the feature.
- **Logs stay in English.** They are easier to search, report, and compare.
- **API errors are stable codes plus an English fallback.** The UI can translate known codes; unknown errors fall back to the server message.

## Catalogs

```
site/i18n/en.json
site/i18n/es.json
core/modules/<id>/i18n/en.json
core/modules/<id>/i18n/es.json
```

Core keys live in `site/i18n/` and are namespaced by page or area:

```
common.*
time.*
index.*
fleet.*
control.*
notifications.*
nodo.*
terminal.*
modules.*
```

Each module keeps its own strings in `core/modules/<id>/i18n/{en,es}.json` (for example `printer.*`, `module.octoprint.*`, `advisor.*`, `module.advisor.*`). When the browser loads `/hub/i18n/<lang>.json`, the hub merges the active module catalogs into the response automatically. The core catalogs never name specific modules.

Both `en.json` and `es.json` must have the exact same key set; `tests/test_unit.py` checks parity.

## Runtime

- `site/i18n.js` loads `api/caps` once to read the instance default (`config.lang`, default `en`), then checks `?lang=`, `localStorage`, and the default.
- The language button in the header switches between English and Spanish and reloads the page.
- Control also has an explicit language selector.
- `data-i18n`, `data-i18n-html`, `data-i18n-aria`, `data-i18n-placeholder`, `data-i18n-title`, and `data-i18n-content` are applied automatically.
- Dynamic strings use `I18N.t(key, vars)`; plurals use `I18N.tn(key, n, vars)`.
- Dates and times use `I18N.locale` (`en-US` / `es-MX`).
- Missing keys fall back to English, then to the key itself.

## Adding a string

1. Add the English key to `site/i18n/en.json`.
2. Add the Spanish key to `site/i18n/es.json`.
3. Use `data-i18n` for static HTML or `T("key")` in JS.
4. For placeholders, use `{name}`, `{n}`, `{error}`.
5. Test both languages at 390 px width. Spanish text is usually longer.

## Adding a language

1. Add the code to `SUPPORTED` in `site/i18n.js`.
2. Create `site/i18n/<code>.json` with the same keys.
3. Add the option to the language selector and the header toggle if desired.
4. Add date/number locale mapping in `I18N.locale`.
5. Run the parity test and a visual review.

Do not ship machine-translated security warnings or destructive-action confirmations without a human review.

## Module strings

Module manifests reference i18n keys for their labels and navigation items (for example `module.octoprint.url`), and provide those keys in their own `core/modules/<id>/i18n/{en,es}.json` files. Module notification events use `notifications.event.<key>`.

## Documentation

- `README.md`: English, primary.
- `README.es.md`: Spanish translation.
- Technical docs in `docs/` are English. Translate only the guides that users need in Spanish; keep both versions in sync.
